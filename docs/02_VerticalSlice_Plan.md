# 02. Vertical Slice 계획 — MILESTONE 01: THE FIRST RETURN

> 목표 (핸드오프 33장): 도착 → 성 진입 → 기절 → 기상 → **닫힌 성문** → **경비가 나를 기억함** → 다시 기절.
> 끝날 때 플레이어가 "다음엔 뭐가 달라질까?"라고 생각하면 성공.

---

## 1. 비트 시트 (현재 데이터 기준, 전부 임시 대사)

텍스트로 바로 해볼 수 있다: `python Tools/narrative/btg.py play`

### 1회차 — `S01_Arrival` (정상 세계를 외우는 날)
| 장소 | 일어나는 일 | 데이터 |
|---|---|---|
| 마을 입구 | 도착. 길 끝 언덕 위로 **열린 성문이 보인다** | `world: gate.state=open` |
| 광장 | 술집 간판(거품 넘치는 맥주잔)을 **정상 상태로 학습** | `tavern_sign.state=normal` |
| 술집 | 첫 만남 농담 → 혼잣말 "……장작이 얼마 안 남았네." (부탁 아님) → 왕 이야기: "재밌는 분이셔. 한번 올라가 봐." | `bartender.c1.*` |
| 대장간 앞 | 장작더미. 들 수 있다 (인벤토리 없음, 회차 플래그 하나) | `firewood.take` |
| 술집 | 장작을 내밀면 "시키지도 않았는데?" → 내부적으로 `HelpedWithoutReward` 기록. UI엔 아무것도 안 뜸 | `bartender.firewood.give` |
| 성문 | 평범한 경비. "안에서 뛰지만 마시오. 바닥 닦은 지 얼마 안 됐소." | `guard.c1.*` |
| 성 현관 | 진입 직후 이명 → 흐림 → 흔들림 → 그래픽 이상 → 쓰러짐 → 암전 | `castle.c1.enter` → `faint:CastleInterior` |

### 2회차 — `S02_GateClosed` (어? 어제랑 다른데?)
| 장소 | 일어나는 일 | 데이터 |
|---|---|---|
| 마을 입구 | 눈을 뜬다. 같은 자리. **성문이 닫혀 있다** — 아무도 말해주지 않는다 | `rule: gate.state=closed when stage>=S02` |
| 술집 | (장작을 줬다면) "어제 장작 가져다준 거 고맙더라." → "어제 성은 어땠어?" → "쓰러져? 우리 가게 술도 안 마셨는데?" — **성문 얘기는 절대 안 함** | `bartender.c2.*` (`rel:...@prev`) |
| 술집 (1회차에 건너뛴 경우) | "아, 어제 성 앞에서 쓰러졌다던 그 외지인이구나? 소문 빠르지?" | `bartender.c2.first_meet` |
| 성문 | "어제는 들어갈 수 있었잖아." / "어제?" / (정적) "……어디서 본 것 같은데." / (정적) "아. 어제 성문 앞에서 쓰러진 사람이 자네였나?" | `guard.c2.recognize` |
| 성문 | "성 안에서 쓰러졌는데." → "……내가 봤을 땐 여기, 이 문 앞이었소." (첫 어긋남) | `guard.c2.where` |
| 성문 | 닫힌 성문을 만진다 → 경비 "이봐, 손대지 말라니까—" → 기절 | `gate.c2.touch` → `faint:GateTouch` |
| 성문 (경비를 무시한 경우) | 먼저 만지려 하면 경비가 가로막고 알아보는 비트로 연결 — **핵심 비트는 건너뛸 수 없다** | `gate.c2.intercept` |

### 3회차 — `S03_SliceEnd` (임시 티저)
눈을 뜬다. "마을 입구다. 또." 광장에 가면 **술집 간판이 거꾸로 걸려 있다.** 슬라이스 종료 카드.

---

## 2. 레벨 블록아웃 요구사항

- **시야선**: 마을 입구 → 광장 → 성문이 거의 일직선. 기상 지점에서 성문 실루엣이 화면 중앙 상단에 보여야 한다. 열림/닫힘이 **실루엣 차이**로 즉시 읽혀야 한다 (밝은 안쪽 vs 막힌 면).
- **거리**: 입구→성문 걸어서 40초 이내. 술집·대장간은 광장에서 10초 이내.
- **간판**: 광장에서 정면으로 보이는 위치. 1·2회차 동안 여러 번 시야에 들어와야 3회차 변화가 먹힌다.
- **성 현관**: 성문 통과 후 3~4m 안에 볼륨. 현관 내부는 거의 안 보여줘도 된다.
- 대장장이는 VS 범위 밖. 대장간은 "오늘 휴업" 팻말 + 장작더미만.

## 3. 구현 순서 (각 단계 끝에 실행 가능한 상태)

| 단계 | 내용 | 완료 기준 |
|---|---|---|
| **0** | ✅ 내러티브 코어 (엔진 독립 Python 레퍼런스), 데이터 포맷, 검증기, 텍스트 프로토타입 | `btg.py validate` 0 error, 텍스트로 M01 완주 |
| **1** | ✅ Godot 4.7 프로젝트 + 내러티브 코어 GDScript 이식 + 세이브(A/B) + 공용 시나리오 테스트 | **Godot 안에서 Python과 같은 벡터·시나리오 전부 통과** |
| 2 | 플레이어: 1인칭 이동/시점, 레이캐스트 상호작용 + 프롬프트 | 회색 박스 앞에서 E → `Narrative.trigger()` 로그 |
| 3 | 블록아웃 마을 (2장 요구사항), 앵커/볼륨 배치 | 입구 스크린샷에 성문이 보임, 5개 장소 걸어서 이동 |
| 4 | 대화 UI (타자기, 선택지, 정적) | 술집 주인 1회차 대화가 데이터 그대로 나옴 |
| 5 | 월드 상태 표현 (`gate.state`, `location`, 간판) | 스테이지를 바꾸면 성문이 닫힌 스크린샷 |
| 6 | 회차 파이프라인 (기절 연출 → `complete_cycle()` → 씬 리로드 → 기상) | 성 현관 진입 → 2회차 기상까지 끊김 없이. 자동 플레이 테스트 |
| 7 | 페이크 보이스 (`VoiceProfile.tres` + 노드), 임시 블립 샘플 | 술집 주인/경비 목소리가 눈 감고도 구분됨 (**오너 귀로 확인**) |
| 8 | 메인 메뉴 이어하기 / 새로 하기 | 2회차에서 종료 → 재실행 → 2회차 시작 지점 |
| 9 | 사운드 1차: **정상 마을 환경음을 풍부하게** + 오디오 버스 구성 | 1회차가 "살아 있는 마을"로 들림 (**오너 귀로 확인**) |
| 10 | 플레이테스트 → 4장 질문 → 수정 | 7번 질문에 YES |

각 단계는 AI가 헤드리스 테스트와 스크린샷으로 1차 확인한다. 손맛·소리는 오너가 확인한다.

## 4. 플레이테스트 체크리스트 (핸드오프 31장)

텍스트 프로토타입 단계에서도 2·3·4·6·7번은 미리 볼 수 있다.

1. 마을을 돌아다니는 것 자체가 지루하지 않은가?
2. NPC 대화가 자연스러운가?
3. 1회차에서 플레이어가 성에 관심을 가지는가?
4. 첫 기절이 궁금증을 만드는가?
5. 2회차에서 성문이 닫힌 것을 **즉시** 눈치채는가? (측정: 기상 후 첫 시선/첫 발화)
6. 경비가 플레이어를 기억하는 순간이 흥미로운가?
7. **플레이어가 "다음 회차에는 뭐가 바뀌지?"라고 생각하는가?** → 실패하면 콘텐츠 추가가 아니라 반복 구조 수정

## 5. 자동 검증 (지금 있는 것)

Python(`Tools/narrative/tests`)과 Godot(`tests/`)이 아래 공용 파일을 **둘 다** 실행한다.

| 공용 테스트 | 지키는 것 |
|---|---|
| `scenarios/m01_golden_path.json` | 위 비트 시트 전체 흐름 + 1·2회차 NPC가 "또 시작/이번에도/또 왔" 류 대사를 하지 않음(핸드오프 12장) + 2회차 술집 주인이 성문이 닫혔다고 말하지 않음(성공조건 5) |
| `scenarios/m01_skip_everyone.json` | 아무와도 안 얘기하고 성으로 직행해도 2회차 핵심 비트가 나온다 |
| `scenarios/m01_yesterday_means_yesterday.json` | "어제 장작"은 정확히 전날에만 (이틀 뒤에 '어제'라고 하면 거짓말) |
| `condition_vectors.json` | 조건 DSL 동작 |
| `fixtures/semantics/` | 우선순위, once, 선택지, 체인, 스테이지 전환, 월드 규칙 |

그 밖에: 모든 스테이지에서 모든 NPC가 대답함, 세이브 손상/조작/버전 처리, 실제 데이터 0 error/0 warning, 텍스트 워크스루 완주.

## 6. 임시 vs 최종 구분

|---|---|
| `GameData/` | **실제 게임 데이터.** 단, 현재 대사는 전부 임시 (비트 `note`에 `[임시 대사]`/`제안:` 표시) |

## 7. 지금까지 구현된 것

**단계 0 — 엔진 독립 내러티브 코어.** 게임의 뇌(무엇을, 언제, 누가 기억하는가)를 엔진보다 먼저 확정하고 테스트로 고정했다. 대사와 회차 흐름은 지금 바로 텍스트로 플레이할 수 있다.
- `GameData/` — 레지스트리, 대상, 스테이지, 월드(baseline+rules), 비트(술집 주인/경비/소품)
- `Tools/narrative/` — Python 레퍼런스(조건/효과, 로더, 검증기, 엔진, 세이브, 텍스트 프로토타입)

**단계 1 — Godot 4.7 런타임.**
- `project.godot` (저장소 루트), autoload `Narrative`
- `core/narrative/` — 위 레퍼런스의 GDScript 이식 + A/B 슬롯 세이브
- `tests/` — 애드온 없는 헤드리스 테스트 러너. Python과 **같은** 조건 벡터, 시나리오, 픽스처 실행
- `GameData/tests/scenarios/` — M01 스토리 검사를 데이터로 (두 구현이 같은 파일 실행)
- CI: `python-reference` + `godot-runtime` 두 잡

**다음: 단계 2~3** — 1인칭 컨트롤러 + 회색 박스 마을, 기상 지점 스크린샷으로 성문 시야선 확인.
