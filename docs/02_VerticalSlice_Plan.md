# 02. Vertical Slice 계획 — MILESTONE 01: THE FIRST RETURN

> 목표 (핸드오프 33장): 도착 → 성 진입 → 기절 → 기상 → **닫힌 성문** → **경비가 나를 기억함** → 다시 기절.
> 끝날 때 플레이어가 "다음엔 뭐가 달라질까?"라고 생각하면 성공.

---

## 1. 비트 시트 (현재 데이터 기준, 전부 임시 대사)

텍스트로 바로 해볼 수 있다: `python Tools/narrative/btg.py play`

### 1회차 — `S01_Arrival` (정상 세계를 외우는 날)
| 장소 | 일어나는 일 | 데이터 |
|---|---|---|
| 마을 입구 | 도착. 길 끝 언덕 위로 **열린 성문이 보인다** | `world: gate.state=open` |
| 광장 | 술집 간판(거품 넘치는 맥주잔)을 **정상 상태로 학습** | `tavern_sign.state=normal` |
| 술집 | 첫 만남 농담 → 혼잣말 "……장작이 얼마 안 남았네." (부탁 아님) → 왕 이야기: "재밌는 분이셔. 한번 올라가 봐." | `bartender.c1.*` |
| 대장간 앞 | 장작더미. 들 수 있다 (인벤토리 없음, 회차 플래그 하나) | `firewood.take` |
| 술집 | 장작을 내밀면 "시키지도 않았는데?" → 내부적으로 `HelpedWithoutReward` 기록. UI엔 아무것도 안 뜸 | `bartender.firewood.give` |
| 성문 | 평범한 경비. "안에서 뛰지만 마시오. 바닥 닦은 지 얼마 안 됐소." | `guard.c1.*` |
| 성 현관 | 진입 직후 이명 → 흐림 → 흔들림 → 그래픽 이상 → 쓰러짐 → 암전 | `castle.c1.enter` → `faint:CastleInterior` |

### 2회차 — `S02_GateClosed` (어? 어제랑 다른데?)
| 장소 | 일어나는 일 | 데이터 |
|---|---|---|
| 마을 입구 | 눈을 뜬다. 같은 자리. **성문이 닫혀 있다** — 아무도 말해주지 않는다 | `rule: gate.state=closed when stage>=S02` |
| 술집 | (장작을 줬다면) "어제 장작 가져다준 거 고맙더라." → "어제 성은 어땠어?" → "쓰러져? 우리 가게 술도 안 마셨는데?" — **성문 얘기는 절대 안 함** | `bartender.c2.*` (`rel:...@prev`) |
| 술집 (1회차에 건너뛴 경우) | "아, 어제 성 앞에서 쓰러졌다던 그 외지인이구나? 소문 빠르지?" | `bartender.c2.first_meet` |
| 성문 | "어제는 들어갈 수 있었잖아." / "어제?" / (정적) "……어디서 본 것 같은데." / (정적) "아. 어제 성문 앞에서 쓰러진 사람이 자네였나?" | `guard.c2.recognize` |
| 성문 | "성 안에서 쓰러졌는데." → "……내가 봤을 땐 여기, 이 문 앞이었소." (첫 어긋남) | `guard.c2.where` |
| 성문 | 닫힌 성문을 만진다 → 경비 "이봐, 손대지 말라니까—" → 기절 | `gate.c2.touch` → `faint:GateTouch` |
| 성문 (경비를 무시한 경우) | 먼저 만지려 하면 경비가 가로막고 알아보는 비트로 연결 — **핵심 비트는 건너뛸 수 없다** | `gate.c2.intercept` |

### 3회차 — `S03_SliceEnd` (임시 티저)
눈을 뜬다. "마을 입구다. 또." 광장에 가면 **술집 간판이 거꾸로 걸려 있다.** 슬라이스 종료 카드.

---

## 2. 레벨 블록아웃 요구사항

- **시야선**: 마을 입구 → 광장 → 성문이 거의 일직선. 기상 지점에서 성문 실루엣이 화면 중앙 상단에 보여야 한다. 열림/닫힘이 **실루엣 차이**로 즉시 읽혀야 한다 (밝은 안쪽 vs 막힌 면).
- **거리**: 입구→성문 걸어서 40초 이내. 술집·대장간은 광장에서 10초 이내.
- **간판**: 광장에서 정면으로 보이는 위치. 1·2회차 동안 여러 번 시야에 들어와야 3회차 변화가 먹힌다.
- **성 현관**: 성문 통과 후 3~4m 안에 볼륨. 현관 내부는 거의 안 보여줘도 된다.
- 대장장이는 VS 범위 밖. 대장간은 "오늘 휴업" 팻말 + 장작더미만.

## 3. 구현 순서 (각 단계 끝에 실행 가능한 빌드)

| 단계 | 내용 | 완료 기준 |
|---|---|---|
| **0** | ✅ **내러티브 코어 (엔진 독립)** — 데이터 포맷, 검증기, 레퍼런스 엔진, 텍스트 프로토타입, 테스트 | `btg.py validate` 0 error, 테스트 통과, 텍스트로 M01 완주 (**이번 작업**) |
| 1 | 엔진 확정 + 프로젝트 생성 (UE5 C++ 1인칭 템플릿), Git LFS, `.gitattributes`, 모듈 `BackToTheGates` | 오너 로컬에서 에디터 실행, 빈 맵에서 걷기 |
| 2 | 플레이어: 이동/시점/상호작용 트레이스 + 프롬프트 | 큐브에 E 누르면 로그 |
| 3 | 블록아웃 맵 (2장 요구사항), 앵커/볼륨 배치 | 입구에서 성문 보임, 5개 장소 걸어서 이동 |
| 4 | `UBTGNarrativeSubsystem` + JSON 로더 + 조건 파서 | **UE Automation Spec이 `condition_vectors.json` 전부 통과** |
| 5 | 대화 UI (타자기, 선택지, 정적) + `UBTGDialogueRunner` | 술집 주인 1회차 대화가 데이터 그대로 나옴 |
| 6 | 페이크 보이스 (`UBTGVoiceProfile` + 컴포넌트), 임시 블립 샘플 | 술집 주인/경비 목소리가 눈 감고도 구분됨 |
| 7 | 월드 상태 (`gate.state`, `location`, 간판) | 스테이지를 콘솔로 바꾸면 성문이 닫힘 |
| 8 | 회차 파이프라인 (기절 연출 BP → 전환 → 리로드 → 기상) | 성 현관 진입 → 2회차 기상까지 끊김 없이 |
| 9 | 세이브/로드 (A/B 슬롯, 체크섬), 메인 메뉴 이어하기 | 2회차에서 종료 → 재실행 → 2회차 시작 지점 |
| 10 | 사운드 1차: **정상 마을 환경음을 풍부하게** (새, 바람, 술집 음악, 발소리) + Sound Class 계층 | 1회차가 "살아 있는 마을"로 들림 |
| 11 | 플레이테스트 → 3장 질문 → 수정 | 7번 질문에 YES |

각 단계는 독립 PR. 엔진 코드 단계(1~)는 이 클라우드 환경에서 빌드할 수 없으므로, 오너가 로컬에서 빌드/실행 확인 후 머지한다.

## 4. 플레이테스트 체크리스트 (핸드오프 31장)

텍스트 프로토타입 단계에서도 2·3·4·6·7번은 미리 볼 수 있다.

1. 마을을 돌아다니는 것 자체가 지루하지 않은가?
2. NPC 대화가 자연스러운가?
3. 1회차에서 플레이어가 성에 관심을 가지는가?
4. 첫 기절이 궁금증을 만드는가?
5. 2회차에서 성문이 닫힌 것을 **즉시** 눈치채는가? (측정: 기상 후 첫 시선/첫 발화)
6. 경비가 플레이어를 기억하는 순간이 흥미로운가?
7. **플레이어가 "다음 회차에는 뭐가 바뀌지?"라고 생각하는가?** → 실패하면 콘텐츠 추가가 아니라 반복 구조 수정

## 6. 임시 vs 최종 구분

| 위치 | 성격 |
|---|---|
| `GameData/` | **실제 게임 데이터.** 단, 현재 대사는 전부 임시 (비트 `note`에 `[임시 대사]`/`제안:` 표시) |

## 7. 첫 번째 실제 구현 작업 (완료)

**엔진 독립 내러티브 코어 + Milestone 01 데이터 + 텍스트 프로토타입.**

왜 이것부터인가:
- 엔진이 미정이고 이 환경에선 엔진 빌드가 불가능하다. 그래도 **게임의 뇌(무엇을, 언제, 누가 기억하는가)는 지금 확정하고 테스트로 고정할 수 있다.**
- 엔진에 무엇을 포팅하든 동작 기준(레퍼런스)과 테스트 벡터가 생긴다.
- 대사와 회차 흐름을 엔진 없이 지금 바로 플레이해 볼 수 있다. 2회차 "어제?"의 타이밍이 먹히는지는 블록아웃보다 먼저 확인할 수 있다.

만든 것:
- `GameData/` — 레지스트리(플래그/관계 이벤트/cue/기절 사유), 대상, 스테이지, 월드(baseline+rules), 비트(술집 주인/경비/소품)
- `Tools/narrative/btg_narrative/` — 조건/효과 파서, 로더, 검증기, 엔진(`NarrativeEngine`, `DialogueSession`), 세이브(체크섬+백업+마이그레이션), 텍스트 프로토타입
- `Tools/narrative/tests/` — 위 5장
- `.github/workflows/narrative.yml` — push/PR마다 검증 + 테스트

**다음 작업 (엔진 확정 후)**: 3장 1단계. 오너가 로컬에서 UE5 프로젝트를 생성해 push → 4단계(내러티브 서브시스템 C++ 포팅 + 벡터 테스트)를 작은 PR로.
